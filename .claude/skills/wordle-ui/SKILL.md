# UI & animation

## Colors & theme
- **Themed colors:** `const { color, textColor } = useTheme()`. `color('token')` is for View colors (`backgroundColor`, `border*Color`), `textColor('token')` for Text `color`; both are the same shared, memoized Animated interpolation per token of one native-driven `progress` value, so they only work on `Animated.View`/`Animated.Text` styles. Never put either on a style prop outside RN's native-animated allowlist (`NativeAnimatedAllowlist.js`: background/border colors, `color`, `tintColor`) — e.g. `textShadowColor` must be the `theme` snapshot. A new themed color goes into `ThemeTokens` plus both `lightTheme` ("apricot") and `darkTheme` ("pomegranate night", the default look) in `constants/theme.ts`. Redesign tokens: `backgroundGlow` (the top glow), `raised` (chips, tracks, inner fills), `accent`/`accentEdge` (pomegranate). `ScreenGlow` (`components/ScreenGlow.tsx`) is the soft radial glow at the top of every screen: put it first inside a screen's root; it draws both themes' gradients once and picks one by opacity from `useTheme().darkness` (0/1).
- **`theme` / `isDark` (plain snapshot):** from `useThemeSnapshot()`, never `useTheme()` (the context is split, docs/adr/0005). Only where Animated can't go (LinearGradient `colors`, SymbolView `tintColor`, IconButton `color`, StatusBar, text shadows, non-color logic). They flip once per switch and re-render every reader — so read them only in small leaf components (`components/ThemedSnapshot.tsx`: `ThemedSymbol`, `ThemedIconButton`, `ThemeToggleButton`, `ThemedStatusBar`), never in App, Header, Keyboard, a flow or anything large. Render-time logic that runs anyway for another reason (a key's own state fade) may read `useTheme().currentTheme()` without subscribing.
- **Fixed colors:** game-art colors (gold coin and ribbon gradients, white text on scored tiles, confetti, the praise word's gold → pomegranate shine, Home's gold rosette, the avatars — colored discs with the name's first letter in white, `AVATARS` in `constants/profile.ts` — and the fortune-wheel icon) are deliberately the same in both themes and written as local literals. `INVALID_COLOR` and `NEUTRAL_TILE_*` are shared fixed constants. Don't move these into the theme.
- **Theme switch (circle reveal, docs/adr/0006):** `toggleTheme(origin)` (`lib/ThemeContext.tsx`) snapshots the root view (Skia `makeImageFromView`, `lib/captureView.ts`), mounts `ThemeRevealOverlay` (a full-window Skia canvas showing the snapshot), switches the theme **instantly** underneath once it has painted (`progress.setValue`, the snapshot flips, `onDarkChange` saves), then grows a circular hole in the snapshot from `origin` over `THEME_REVEAL_MS` (650, `Easing.bezier(0.22, 1, 0.36, 1)`) on the UI thread — a Reanimated shared value, the one allowed exception to "Animated only" — and unmounts. A theme control calls `useToggleThemeFrom(ref)`, which measures the pressed control (`measureWindow`; null → the screen's center). Taps mid-reveal are ignored (busy guard); reduced motion or a failed snapshot switch instantly. Never animate a theme color, never add per-frame JS, never remount on a theme change. Jest has a tiny Skia mock (`jest.setup.ts`): `makeImageFromView` resolves null, so switches are instant in tests unless a test mocks an image (`lib/ThemeContext.test.tsx`). The dark choice is saved (`wordle:darkMode`): `ThemeProvider`'s `onDarkChange` hears every player change at the switch and App saves it; at launch App calls `useTheme().setDarkInstant(saved)` in the same batch as the first load, so a dark player never sees a light frame.
- **Yellow/gold means "wrong position":** never use it to highlight correct or ghost letters. Ghost tiles get a one-shot white shine sweep instead (`Tile.tsx`), only when their row becomes active.
- **Ghost kinds (`Tile` `ghostKind`):** a Hint ghost is the letter in `textColor('correct')` at `GHOST_OPACITY` (pale); it animates only once, when a Hint's light lands on it (see Hint flight), and is static otherwise (e.g. backspace bringing it back). A carried ghost (found green before a retry) is the letter at full strength in `textColor('correct')` inside a `color('correct')` outline, on an otherwise empty (transparent) tile — never a fill (that reads as a scored tile) and never yellow. Typing in the cell hides either, and the outline goes with it.
- **Dark mode is in-app only:** `app.json` pins `userInterfaceStyle: light`, so system-scheme APIs (`useColorScheme`, a StatusBar `'auto'` style) always report light. Branch on `useThemeSnapshot().isDark` instead.

## Animation
- **Library:** React Native `Animated` only. The one exception is the theme switch's Skia circle reveal (`ThemeRevealOverlay`), which runs on a Reanimated shared value.
- **Performance (mid-range Android):** animate only transform/opacity/colors on the native driver; never animate a blur or big shadows; no `setState` per frame. `useCountUp` still sets state per frame — don't spread it.
- **Re-renders (low-end Android, docs/adr/0005):** App re-renders on every keystroke, so a keystroke must re-render only the typed row (Board, that Row, ≤ 2 Tiles) — `App.renderCount.test.tsx` enforces it, and Keyboard, Header, BottomControls, WinFlow, LossFlow and ShopScreen must stay at 0. Every component App renders is `React.memo` (React Compiler isn't used: it doesn't run under Jest). Props into a memoized child must be stable: handlers through `useStableCallback` (`lib/useStableCallback.ts`) or `useCallback`, derived arrays/objects through `useMemo`, and shared module constants instead of inline `[]`/`{}` (`EMPTY_ROW`, `NO_GHOSTS`, `NO_TOKENS`, `BACKSPACE_ICON`, `HINT_ICON`); per-item handlers memoized as a map (Keyboard's `pressHandlers`). Never create Animated interpolations during render in a component that re-renders often — memoize them (`usePushPage`'s controller), or the native graph re-attaches each time. Tests look memoized components up with `unmemo(X)` (`test-utils/unmemo.ts`).
- **Board reset** (retry, next word, new game; `resetBoard` in `App.tsx`): the reset commits while the modal still covers the board, and `Board` remounts under a new `key`, so old tiles never morph into new ones. The modal fades out only after that. Never animate the old board away.
- **Tiles:** typing plays only a scale pop; deleting is instant (no exit animation). A just-submitted tile keeps its active, filled look until its own flip reaches 90°.
- **Keys:** a key's state change fades the background, but the label switches color in one step at the midpoint. Fading label and background together makes the label vanish.
- **Creating values:** `useState(() => new Animated.Value(x))`. `useRef(...).current` read during render fails the `react-hooks/refs` lint.
- **Native driver:** `true` for transform, opacity and colors (`backgroundColor`/`border*Color`/Text `color` — RN 0.86 interpolates colors natively on iOS and Android); `false` for layout props and numeric listeners (and a keyboard key's own brief state fade, where label and background share one JS value). Never put a JS-driven value and a native-driven one on the same node. The comment above `KEY_EDGE_HEIGHT` in `constants/theme.ts` explains why 3D edges are separate Views.
- **Durations:** in `constants/theme.ts` (board, keyboard, Darts, rules popup) and `constants/winFlow.ts` (end-of-round flows). No inline magic numbers in new work.
- **Coupled timings:** `App.tsx` schedules game logic with `setTimeout` sums of these constants, and each sum must match what the component plays. If you change a sequence, update its sum:
  - `ROW_REVEAL_DURATION_MS` ↔ the Tile flip plus its stagger
  - the Darts unlock total in `handleDarts` ↔ the ArrowOverlay and BowIcon sequences
  - `LOSS_SHAKE_DURATION_MS` ↔ the Row loss shake
  - the Hint flight in `handleHint` (land after `HINT_FLIGHT_MS`, free the power-ups after `HINT_FLIGHT_MS + HINT_SPARKS_MS`) ↔ `HintFlightOverlay`'s flight + spark sequence and Tile's landing entrance (`HINT_SPARKS_MS`)
- **Reduced motion:** `useTheme().reduceMotion`. App, WinFlow, LossFlow, ResultModal, SecondChanceModal, RulesModal, RulesCard, BowIcon, Tile's Hint entrance, Row's win jump, MenuBackground, Home's logo/streak chip/cards (`RiseIn`), `TabEnter`, `useModalRise`, the tab bar, the theme reveal and useCountUp skip flights and confetti and use short fades or instant values. New heavy motion needs a reduced path. Tile's flip and KeyboardKey don't check it.
- **Idle loops (`lib/useLoopWhile.ts`):** `useLoopWhile(running, make, reset)` starts a native loop while `running` and stops/resets it otherwise. Home's idle motion passes `running = !backgroundPaused && appActive && !reduceMotion` (the menu background's rules).
- **Press feeling (`components/PressScale.tsx`):** big buttons and cards shrink to `PRESS_SCALE` while pressed and spring back (native) with the `button` sound: `PressScale` (a Pressable) or `Button3D pressScale` (both through `usePressScale`). Used on the mode cards, shop packs, the ad card, ՍՏԱՆԱԼ, Settings rows and the flows' modal buttons. Never on small text links, the keyboard or ԸՆԴՈՒՆԵԼ.
- **Sounds:** every sound goes through `lib/sounds.ts` (`playSound(name)`, `playRowFlipSounds()`), the twin of `lib/haptics.ts`: `SOURCES` is the one name → file mapping (`assets/sounds/`, credits in `CREDITS.md`), players are created once at launch (`loadSounds`, pooled for key/flip/coin/button), master volume 0.4, `playsInSilentMode: false`, `mixWithOthers`, failures silent. Gated by ՁԱՅՆԵՐ (`setSoundsEnabled`, `wordle:sounds`, default on, loaded before the first render). Never per frame; one key sound per touch down (and per Backspace repeat). Jest mocks `expo-audio` in `jest.setup.ts`.
- **Haptics:** every haptic goes through `lib/haptics.ts` (never import `expo-haptics` elsewhere): `triggerKeyHaptic`, `triggerLightImpact`, `triggerWarningHaptic`, `triggerHintLandingHaptic`, `triggerWinHaptic` (a success notification + two light taps, at the celebration), `triggerLossHaptic` (one soft bump, at a loss) — each checks the Settings switch's flag (`setHapticsEnabled`, loaded from `wordle:haptics` before the first render) and `.catch(() => {})`s. Key taps go through `triggerKeyHaptic` (also used by ԸՆԴՈՒՆԵԼ): Android `performAndroidHapticsAsync(AndroidHaptics.Keyboard_Tap)` (the system keyboard click via the haptics engine; `impactAsync` on Android is a buzzy Vibrator pulse — don't use it for frequent taps), iOS `selectionAsync()`. One haptic per touch down (and per Backspace repeat).

## Positions & layout
- **Hint flight (`HintFlightOverlay`):** always mounted next to `ArrowOverlay`, outside the SafeAreaView; the light (a bright core in a faint halo disc — no blur, no shadow) and `HINT_SPARK_COUNT` sparks are pre-mounted at opacity 0, so a Hint only starts animations: the light follows a sampled Bézier (`HINT_ARC`) for `HINT_FLIGHT_MS`, then the sparks burst for `HINT_SPARKS_MS`. Fixed greens (never yellow; a theme toggle mid-flight changes nothing). `flight` going null stops and hides it. On landing the target `Tile` breathes (`HINT_BREATH_SCALE`) and the hint ghost scales in from `HINT_GHOST_START_SCALE` (`ghostEntranceId`); reduced motion: no flight, no sparks, no breath — the ghost fades in over `HINT_REDUCED_FADE_MS`. Origin and target are measured at tap time (the Hint button's ref; the active row's tile refs via Board → Row → Tile `cellRef`); either `null` → no flight, the arrival effect in place.
- **Flights and overlays:** positions come from `measureWindow(ref)` (`lib/measureWindow.ts`) at the moment the effect fires, never from an assumed layout. `null` must fall back to a no-flight path. Full-screen overlays that use these window coordinates render outside the SafeAreaView (see `ArrowOverlay` in `App.tsx`).
- **Keyboard geometry:** `computeKeyGeometry` (+ `computeBackspaceGeometry`) in `Keyboard.tsx` re-derives the keyboard layout analytically (rows centered in the window-wide keyboard, also on tablets); Darts aims with it and the touch hit-test uses it. Mirror any key size/gap/row change there. `components/Keyboard.test.tsx` checks key sizes only, not x positions.
- **Keyboard input model:** keys have no touch handling. The Keyboard's root view is the one touch surface (`pointerEvents="box-only"`, `onTouchStart`/`onTouchEnd`/`onTouchCancel` over `nativeEvent.changedTouches`), so simultaneous fingers all register (per-key Pressables would let the responder system give the touch to only one). Each touch is hit-tested by `hitTestKey` on its `locationX/Y` within the surface (always the surface, so no measuring and nothing to redo after a resize): nearest row, then nearest key center — gaps hit their nearest key. Letters and Backspace fire on **touch down**; moving never cancels; ԸՆԴՈՒՆԵԼ and every other button keep firing on release (Pressable). Pressed look: each key's `pressProgress` value, set to 1/0 instantly (`setValue`, no animation, no re-render) while any finger holds it (`Button3D` `touchless` mode). Backspace hold repeats after `BACKSPACE_REPEAT_DELAY_MS`, every `BACKSPACE_REPEAT_INTERVAL_MS`, until that finger lifts. Game rules (isGameLocked, the full-row guard) stay in App's handlers. Accessibility: each key's outer view is an accessible button with its Armenian label and an `activate` accessibility action (→ the same handler); with a screen reader on, the surface ignores touches, so a double-tap never inputs twice.
- **Tile size:** tiles are sized by `fitTileSize` from the board area's `onLayout`; Board renders nothing until that measurement arrives.
- **Popup (`PopupModal`):** the shell of "How to play" (`RulesModal`, `rulesOpen` in `App.tsx`): a centered panel over the shared `ModalBackdrop`, with a title and an X (`Փակել`). Only the X and Android's back button close it, never a backdrop tap. Open/close: opacity + scale on the native driver (`POPUP_*` in `constants/theme.ts`), a plain fade under reduced motion; it unmounts when its close ends. Colors are the `popup*` tokens: a light panel in light, a dark one in dark (the dark `card*` tokens belong to `ResultModal`). It renders last in `App.tsx`, above everything. `RulesCard` is its body (the rules and the example-tile flips, started once it has opened via `onOpened`). It opens by itself once, the first time the player opens the Classic page (`wordle:rulesSeen`, saved as it opens; never on the menu); the header's rules button opens it any time.
- **Shop page (`ShopScreen`):** top bar (back arrow, ԽԱՆՈՒԹ, the live balance), then in a scroll view ՔՈ ՊԱՇԱՐԸ (items held), ՀԶՈՐՈՒԹՅՈՒՆՆԵՐ (a 2×2 grid of item packs, the 5-packs with a green derived discount tag) and ՄԵՏԱՂԱԴՐԱՄՆԵՐ (the rewarded-ad card with today's count, then coming-soon coin packs: dimmed, ՇՈՒՏՈՎ, not pressable). Cards use the `popup*` tokens. Unaffordable packs and a used-up ad are dimmed but tappable, and show their toast in the page's own `Toast`. All numbers and labels in `constants/shop.ts`.
- **Navigation model (`App.tsx`): tabs + push pages.** The main screen is **`MainTabs`**: five tabs over an always-visible **`TabBar`**, left to right — ԽԱՆՈՒԹ (the Shop tab: `ShopScreen` without `onBack`), ԱՌԱՋԱԴՐԱՆՔՆԵՐ, **ՄԵՆՅՈՒ = Home, the center tab, where the app opens** (`MenuScreen`), ԱՌԱՋԱՏԱՐՆԵՐ, ԿԱՐԳԱՎՈՐՈՒՄՆԵՐ (Leaderboard is still an empty `EmptyPage` without `onBack`: title only; Tasks is `TasksScreen`, Settings is `SettingsScreen`). The fortune wheel is not a tab: it's a button on Home. App owns `activeTab` and passes memoized `tabContents` (stable across keystrokes). Pushed over the tabs with `usePushPage()`/`PushPageLayer`: the **Classic game page** (`gamePage`, `preMount testID="page-game"`, never unmounted; its flows and overlays live inside it), the **fortune wheel page** (`wheelPage`, `page-wheel`, from Home's wheel button: ԲԱԽՏԻ ԱՆԻՎ + back), and the **shop page** (`page-shop`, from the game's coin pill or a 0-item power-up — a second `ShopScreen` with its back arrow). Layers, bottom to top: the tabs (wrapped in the game and wheel pages' `gameTranslateX`, inert and hidden from screen readers while any page is on top, so the bar is covered too) → the game page → the wheel page → all of that in the shop's `gameTranslateX` → the shop page → `RulesModal` → `ProfileModal` → `ThemedStatusBar`. Home's coin pill switches to the Shop tab; inside the game the pill pushes the shop page. Android back: a page/popup handles it first (registered later; the game page also yields to the rules popup/shop via `isCovered`); otherwise App's handler — registered once at mount, standing aside while anything covers the tabs — sends any non-Home tab Home, and on Home returns false (the system exits). Back from the game lands on the tab that was active (Home). The rules popup auto-opens on the first Classic open (`wordle:rulesSeen`).
- **Tabs (`MainTabs`/`TabBar`, memoized):** tabs mount on their first visit and stay mounted (React state kept). A switch slides the old content out and the new in toward the new tab's side (one `Animated.Value` per tab for translateX, native, `TAB_SLIDE_MS`; reduced motion: instant). **Inactive tabs are `display: 'none'` once the slide ends** (on a plain outer view; the transform is on an inner `Animated.View`), plus `pointerEvents="none"` and hidden from screen readers — never hidden by transform/opacity alone: on a Redmi a view hidden only that way (the pre-mounted game page) stayed on screen (an open Android bug). **The bar floats** over the content (`TAB_BAR_INSET` from the sides and bottom + the bottom inset, `TAB_BAR_RADIUS`, `surface` with a `border` line and a static soft shadow; iOS: a static `BlurView` under an 86% surface tint, a snapshot leaf for its tint; Android: opaque, no blur). Every tab's scroll content keeps `TAB_BAR_SPACE + insets.bottom` free at its bottom (Shop only as a tab). A raised bubble (`raised`, `keyEdge` bottom) springs between the cells: one native `bubbleIndex` × a cell-width `Animated.Value` fed with `setValue` (built once). Per tab one 0→1 value (native, built once, `TAB_ACTIVATE_MS`, back-eased) lifts the icon (`TAB_ICON_LIFT`, `TAB_ICON_ACTIVE_SCALE`), takes inactive icons to `TAB_INACTIVE_OPACITY` (washed out) and fades/scales the name in under it (`numberOfLines={1}` + `adjustsFontSizeToFit`); the new tab's icon also wiggles (`TAB_WIGGLE_MS`). A label is mounted only for the active tab and the old one until its fade ends. The Tasks badge (`tab-badge-<tab>`) is a pomegranate dot with a pulsing ring (one native loop). Cells: `accessibilityRole="tab"`, Armenian label, `accessibilityState.selected`. Constants `TAB_*` in `constants/theme.ts`. Home's idle motion runs only while Home is what's on screen (`backgroundPaused` = another tab, any page, or the profile/rules popup). `App.tabs.test.tsx`.
- **Tab entrances (`TabEnter`):** each time a tab is shown (`visible` turns true) its cards rise in with a staggered spring (`TAB_ENTER_*`; Shop's packs `kind="pop"`). Tasks: each progress fill slides in from the left to its share (a translateX of a full-width fill inside the clipped track, the track width fed by `setValue` — a transform, never a width animation) with drifting diagonal stripes, and ՍՏԱՆԱԼ pulses (a ring) while claimable. Settings' switch knobs spring.
- **Menu (`MenuScreen`, the Home tab, memoized; App passes stable props incl. `streak`):** top bar — the profile (Avatar, name, `"N ՄԻԱՎՈՐ"`; opens `ProfileModal`: a `PopupModal` titled ՊՐՈՖԻԼ with a name `TextInput` (`maxLength` 16; its colors are snapshot props) and a 4×2 grid of preset avatars (`accessibilityLabel` `ԱՎԱՏԱՐ n`, selected = a `color('correct')` ring); it edits a draft and App saves it on close, X or Android back) and the coin pill (`CoinPillContent` → the Shop tab); under the pill, in its own right-aligned row (never overlapping the logo), the **wheel button** (`WheelButton`, `accessibilityLabel` ԲԱԽՏԻ ԱՆԻՎ → the wheel page): the wheel icon at `WHEEL_BUTTON_SIZE` with a pomegranate `ՊՏՏԻ՛Ր` badge (՛ = U+055B; fixed white text) bobbing (`WHEEL_BADGE_BOB_*`). It idles with one spin every `WHEEL_IDLE_INTERVAL_MS`: a quick ease-out full turn overshooting by `WHEEL_OVERSHOOT_TURNS` (~30°), then an elastic settle — one pre-built native `Animated.loop`, rotate only; only the wheel body turns (`FortuneWheelIcon` `layer` = `base` / `wheel` / `top`); paused under the menu background's rules plus `AppState` (`lib/useAppActive.ts`), reset upright on pause; reduced motion: no spin. `App.wheelButton.test.tsx`. Then the hero: `HomeLogo` (five candy tiles Բ Ա Ռ ՈՒ Կ in `FONTS.display` over a darker bottom edge, alternate ones lower; the tagline ԲԱՌԵՐԻ ԽԱՂ) and the `StreakChip` (`streak-chip`: a pomegranate-tinted pill with a soft halo, the flickering `StreakFlame` at `streakFlameTier(n)` and "N ՕՐ ԱՆԸՆԴՄԵՋ"; when the streak grew since Home was last on screen the number counts up in a few stepped updates with a pop — never per frame; invisible at 0 but keeps its place). The first time Home appears per launch (`introPlayed`, module-level — a progress reset doesn't replay it) the tiles drop in with a spring and stagger, the tagline fades up and the cards/wheel `RiseIn`; afterwards the logo floats in a staggered wave (one native clock loop). Then the cards (`Button3D pressScale`): ԴԱՍԱԿԱՆ (`correct` face with a white sheen gradient, `ShineSweep` every `HOME_SHINE_INTERVAL_MS` (paused off screen), a nudging `PlayIcon` in a translucent box; subtitle from App: `ԽԱՂԱԼ` / `ՇԱՐՈՒՆԱԿԵԼ · N/6` / `ՇԱՐՈՒՆԱԿԵԼ` while an end-of-round phase is pending) and ՕՐՎԱ ԲԱՌ (`surface` face, a `LockIcon` in a `raised` box, ՇՈՒՏՈՎ; a tap only shows its own Toast). The space below the cards is kept free on purpose (more is coming). Only Classic and Word of the day exist — build nothing for other modes.
- **Menu background (`MenuBackground`, behind the menu content, outside the safe area):** an Armenian eight-pointed star rosette (`Rosette`, fixed gold, opacity on its strokes) turning once per `HOME_ROSETTE_TURN_MS` (one native rotate loop, resuming mid-turn after a pause; same pause rules), and ~12 faint letter tiles (in `FONTS.display`) (`MENU_BG_TILES` in `constants/theme.ts`: token, x, size, period, start phase, rotation range, opacity 0.07–0.1, empty-outline or `correct`/`present` fill) drifting upward with a slight rotation, each at its own pace, looping seamlessly (a tile leaves above the screen and re-enters below). It must stay calm and never compete with the cards or hurt legibility — keep opacities this low. Rules: every tile pre-mounted; transform only (translateY + rotate) on the native driver; one `Animated.loop` of a 0→1 `clock` per tile, position = `Animated.modulo(clock + offset, 1)`; no JS per frame, no setState. The loops run only while the menu is on screen: `paused` (App: any page on top) or `AppState` not active stops them (`stopAnimation` folds the clock into `offset`, so resuming continues from the same spot); reduced motion never starts them (tiles stay at their start phase). Per-tile opacity, never a group opacity on the container (an offscreen layer on Android). `App.menuBackground.test.tsx` covers start/stop/reduced motion.
- **Tasks (`TasksScreen`, the Tasks tab, memoized):** a top bar (title + the live balance pill, `tasks-balance`), the note `TASKS_REFRESH_NOTE`, then one card per task (`task-<id>`, `popup*` tokens): the title (2 lines max), `+reward` with a Coin, a progress bar (`TaskProgress`: `correct` fill on `raised`) with `n/target`, and — once done — a green `Button3D` ՍՏԱՆԱԼ, or ՍՏԱՑՎԱԾ (card dimmed) once claimed. A claim: App credits and saves first, then coins fly (`CoinFlight`, in a window-coordinate overlay) from the button to the balance, which steps up per arrival; no measurement → no flight. The tab bar shows a pulsing pomegranate dot (`TabBar` `badges`, `tab-badge-<tab>`) on Tasks while a reward waits; a claim plays the `claim` sound. `App.tasks.test.tsx`.
- **Settings (`SettingsScreen`, the Settings tab, memoized):** the shop's card look (`popup*` tokens), sections ՏԵՍՔ (ՄՈՒԳ ԹԵՄԱ switch — `DarkModeSwitch`, its own snapshot-reading leaf; the reveal spreads from its track), ԽԱՂ (ԹՐԹՌՈՑ switch; ՁԱՅՆԵՐ switch; ԻՆՉՊԵ՞Ս ԽԱՂԱԼ → the rules popup), ՀԱՇԻՎ (ՊՐՈՖԻԼ → the profile popup, showing name + avatar; ՊԱՀՊԱՆԵԼ ԱՐԴՅՈՒՆՔԸ — dimmed, ՇՈՒՏՈՎ tag, a tap only toasts; ԶՐՈՅԱՑՆԵԼ ԱՌԱՋԸՆԹԱՑԸ in fixed red → `ResetConfirmModal`), ԱՅԼ (ԱՌԱՋԱՐԿՆԵՐ ԵՎ ԿԱՐԾԻՔՆԵՐ — coming soon, no destination decided yet; ՄԱՍԻՆ → `AboutModal` with `APP_VERSION` from app.json, `constants/app.ts`). The switches are `SettingsSwitch`: `accessibilityRole="switch"` + `accessibilityState.checked`, a track crossfading `raised` → `correct` and a white knob springing across (native; reduced motion: instant). The reset popup (`SettingsPopups.tsx`): ԶՐՈՅԱՑՆԵԼ (fixed red `Button3D`) or ՉԵՂԱՐԿԵԼ / X / back to cancel. `App.settings.test.tsx`.
- **Pages (`PushPage.tsx`):** a page (the game, the shop page, Settings) is a full screen pushed in from the right like an iOS navigation push — recovered from the old "How to play" page (before b41380f). `usePushPage()` is the controller App owns (one `push` value drives the page's slide and the game's slight left parallax + dim; `gameTranslateX` goes on the game screen); `PushPageLayer` renders the dim and the page. It closes with its back arrow (`Հետ`), Android's back button, or on iOS a swipe from the left edge (the drag *is* the animation; thresholds `PAGE_SWIPE_*`). Once opened it stays mounted (`everOpened`); `onTop` drives inertness. Native driver, `PAGE_*` durations; reduced motion: no movement, a fade. **Two safety rules (a Redmi showed the pre-mounted game over the menu at launch):** (1) the controller's animated nodes are built ONCE — the window width and reduced motion are `Animated.Value`s fed in with `setValue` (`Animated.multiply`/`add` + fixed-range interpolations), never new nodes on a dimension change: when a native-driven props node is swapped, RN's old-node cleanup calls `restoreDefaultValues` (translateX → 0) after the new node attached, and nothing re-applies it. Never build page/parallax nodes in a `useMemo` with layout deps. (2) `PushPageLayer` wraps each page in a plain frame (`testID` `<page>-frame`) that is opacity 0 + `pointerEvents="none"` whenever the controller's `shown` is false — `shown` turns true in `open()` (before its two-frame wait) and false only when a close finishes (button/back animation end, or a completed swipe), so a closed page can't cover anything whatever its transform, the close plays fully, and a swipe's drag stays visible. The dim is mounted only while shown.
- **Coin pill (header, top right):** compact; pressable (`Խանութ`), it opens the shop page (so does a power-up tap with no items and too few coins). Content is `CoinPillContent` — the count, then the B `Coin` with a small green circular "+" badge (`correct` fill, fixed white "+") overlapping the coin's bottom-right corner — inside `coinPillStyles.pill`. WinFlow/LossFlow draw the same content in their duplicate pill above the overlay, so change it only there. The header's `ref` is on the pill's own view (measured for coin flights). Header side groups share the center's flex weight, so the points block is centered.

## Text & icons
- **Fonts:** `FONT_FAMILY` (GHEA Grapalat Bold; `FONTS.tile/title/body` all resolve to it) for everything — board tiles, keys and body text included — except `FONTS.display` (`DISPLAY_FONT_FAMILY`, Noto Serif Armenian Black, OFL, `assets/fonts/`, line height `DISPLAY_LINE_HEIGHT_EM`): Home's logo tiles and drifting tiles, page titles (Shop, Tasks, Settings, empty pages) and the praise word. Copy a sibling component's Text style rather than inventing metrics.
- **Copy and labels:** UI copy is hard-coded uppercase Armenian, with no i18n layer. Accessibility labels are Armenian, and tests find keys by them.
- **Game icons:** custom icons are SVG components that follow `design-system.md` **in the fortune wheel's style** (`FortuneWheelIcon` — the user's reference; the whole app is moving toward it): a 64-unit viewBox; a darker copy of the silhouette offset down-left (`translate(-1.5 3)`) for depth; cheerful gradient fills; one thick rounded brown outline `#6B3A0A` (3 for the main shape, ~2 for details); a soft white highlight stroke on the upper left; fixed game-art colors (the same in both themes, so a theme toggle never re-renders them). The tab bar's icons are in `components/TabIcons.tsx` (`ShopCartIcon`, `BookIcon`, `HouseIcon`, `PodiumIcon`, `GearIcon`; viewBox `2 2 60 60` so they fill their box like the round wheel); check a new icon at 26–36px on light and dark before shipping. Every game icon is in this family now (shared bits in `components/gameIconArt.tsx`): the tab icons, `Coin`, `StreakFlame` (tiers `small`/`big`/`legend`, `streakFlameTier(days)`; `StreakFlameIcon` and `Flame` use it), `HintIcon`, `LockIcon`, `ArcheryArt` (`BowArt`/`ArrowArt`, used by `BowIcon` and `ArrowOverlay` with their animations unchanged), `FortuneWheelIcon`, `PlayIcon`, the theme toggle's sun and moon.
