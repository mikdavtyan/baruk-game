# UI & animation

## Colors & theme
- **Themed colors:** `const { color, textColor } = useTheme()`. `color('token')` is for View colors (`backgroundColor`, `border*Color`) and is native-driven; `textColor('token')` is for Text `color` and is JS-driven. Both return one shared, memoized Animated interpolation per token, so they only work on `Animated.View`/`Animated.Text` styles. Never put `color()` on a Text color or on a style prop outside RN's native-animated allowlist (`NativeAnimatedAllowlist.js`: background/border colors, `color`, `tintColor`) — e.g. `textShadowColor` must be the `theme` snapshot. A new themed color goes into `ThemeTokens` plus both `lightTheme` and `darkTheme` (`constants/theme.ts`).
- **`theme` / `isDark` (plain snapshot):** only where Animated can't go (LinearGradient `colors`, SymbolView `tintColor`, IconButton `color`, StatusBar, text shadows, PNG sources, non-color logic). They flip once, at the midpoint of the theme fade.
- **Fixed colors:** game-art colors (gold coin and ribbon gradients, white text on scored tiles, confetti) are deliberately the same in both themes and written as local literals. `INVALID_COLOR` and `NEUTRAL_TILE_*` are shared fixed constants. Don't move these into the theme.
- **Theme switch:** `toggleTheme()` (`lib/ThemeContext.tsx`) fades every themed color in place over `THEME_FADE_MS`: `progress` (native, View colors) and `textProgress` (JS, Text colors) animate together, in two halves (ease-in to 0.5, ease-out to the end = `Easing.inOut(Easing.quad)`); the snapshot flips in the callback between the halves, not on a timer. Taps mid-fade are ignored (busy guard); reduced motion sets both values and the snapshot instantly. Never remount on a theme change. A brief low-contrast moment mid-fade is accepted and kept short on purpose (`docs/adr/0004-theme-colors-fade-in-place.md`); don't lengthen `THEME_FADE_MS`.
- **Yellow/gold means "wrong position":** never use it to highlight correct or ghost letters. Ghost tiles get a one-shot white shine sweep instead (`Tile.tsx`), only when their row becomes active.
- **Ghost kinds (`Tile` `ghostKind`):** a Hint ghost is the letter in `theme.correct` at `GHOST_OPACITY` (pale). A carried ghost (found green before a retry) is the letter at full strength in `textColor('correct')` inside a `color('correct')` outline, on an otherwise empty (transparent) tile — never a fill (that reads as a scored tile) and never yellow. Typing in the cell hides either, and the outline goes with it.
- **Dark mode is in-app only:** `app.json` pins `userInterfaceStyle: light`, so system-scheme APIs (`useColorScheme`, a StatusBar `'auto'` style) always report light. Branch on `useTheme().isDark` instead. The theme choice isn't persisted.

## Animation
- **Library:** React Native `Animated` only. (Reanimated is installed but nothing imports it.)
- **Performance (mid-range Android):** animate only transform/opacity on the native driver; never animate a blur or big shadows; no `setState` per frame. `useCountUp` still sets state per frame — don't spread it.
- **Board reset** (retry, next word, new game; `resetBoard` in `App.tsx`): the reset commits while the modal still covers the board, and `Board` remounts under a new `key`, so old tiles never morph into new ones. The modal fades out only after that. Never animate the old board away.
- **Tiles:** typing plays only a scale pop; deleting is instant (no exit animation). A just-submitted tile keeps its active, filled look until its own flip reaches 90°.
- **Keys:** a key's state change fades the background, but the label switches color in one step at the midpoint. Fading label and background together makes the label vanish.
- **Creating values:** `useState(() => new Animated.Value(x))`. `useRef(...).current` read during render fails the `react-hooks/refs` lint.
- **Native driver:** `true` for transform, opacity and View colors (`backgroundColor`/`border*Color` — RN 0.86 interpolates colors natively on iOS and Android); `false` for Text `color` (native text color isn't confirmed to repaint on Android), layout props and numeric listeners. Never put a JS-driven value and a native-driven one on the same node. The comment above `KEY_EDGE_HEIGHT` in `constants/theme.ts` explains why 3D edges are separate Views.
- **Durations:** in `constants/theme.ts` (board, keyboard, Darts, rules popup) and `constants/winFlow.ts` (end-of-round flows). No inline magic numbers in new work.
- **Coupled timings:** `App.tsx` schedules game logic with `setTimeout` sums of these constants, and each sum must match what the component plays. If you change a sequence, update its sum:
  - `ROW_REVEAL_DURATION_MS` ↔ the Tile flip plus its stagger
  - the Darts unlock total in `handleDarts` ↔ the ArrowOverlay and BowIcon sequences
  - `LOSS_SHAKE_DURATION_MS` ↔ the Row loss shake
- **Reduced motion:** `useTheme().reduceMotion`. App, WinFlow, LossFlow, ResultModal, SecondChanceModal, RulesModal, RulesCard, BowIcon and useCountUp skip flights and confetti and use short fades or instant values. New heavy motion needs a reduced path. Tile, Row and KeyboardKey don't check it today.
- **Haptics:** always `.catch(() => {})`; key taps go through `lib/haptics.ts`.

## Positions & layout
- **Flights and overlays:** positions come from `measureWindow(ref)` (`lib/measureWindow.ts`) at the moment the effect fires, never from an assumed layout. `null` must fall back to a no-flight path. Full-screen overlays that use these window coordinates render outside the SafeAreaView (see `ArrowOverlay` in `App.tsx`).
- **Keyboard geometry:** `computeKeyGeometry` in `Keyboard.tsx` re-derives the keyboard layout analytically, and Darts aims with it. Mirror any key size/gap/row change there. `components/Keyboard.test.tsx` checks key sizes only, not x positions.
- **Tile size:** tiles are sized by `fitTileSize` from the board area's `onLayout`; Board renders nothing until that measurement arrives.
- **Popup (`PopupModal`):** the shell of "How to play" (`RulesModal`, `rulesOpen` in `App.tsx`): a centered panel over the shared `ModalBackdrop`, with a title and an X (`Փակել`). Only the X and Android's back button close it, never a backdrop tap. Open/close: opacity + scale on the native driver (`POPUP_*` in `constants/theme.ts`), a plain fade under reduced motion; it unmounts when its close ends. Colors are the `popup*` tokens: a light panel in light, a dark one in dark (the dark `card*` tokens belong to `ResultModal`). It renders last in `App.tsx`, above everything. `RulesCard` is its body (the rules and the example-tile flips, started once it has opened via `onOpened`). It opens by itself once, on the very first launch (`wordle:rulesSeen`, saved as it opens); the header's rules button opens it any time.
- **Pages (`PushPage.tsx`):** the shop (`ShopScreen`) is a full page pushed in from the right like an iOS navigation push — recovered from the old "How to play" page (before b41380f). `usePushPage()` is the controller App owns (one `push` value drives the page's slide and the game's slight left parallax + dim; `gameTranslateX` goes on the game screen); `PushPageLayer` renders the dim and the page. It closes with its back arrow (`Հետ`), Android's back button, or on iOS a swipe from the left edge (the drag *is* the animation; thresholds `PAGE_SWIPE_*`). Once opened it stays mounted (`everOpened`); `onTop` drives inertness. Native driver, `PAGE_*` durations; reduced motion: no movement, a fade.
- **Coin pill (header, top right):** compact; pressable (`Խանութ`), it opens the shop page (so does a power-up tap with no items and too few coins). Content is `CoinPillContent` — the count, then the B `Coin` with a small green circular "+" badge (`correct` fill, fixed white "+") overlapping the coin's bottom-right corner — inside `coinPillStyles.pill`. WinFlow/LossFlow draw the same content in their duplicate pill above the overlay, so change it only there. The header's `ref` is on the pill's own view (measured for coin flights). Header side groups share the center's flex weight, so the points block is centered.

## Text & icons
- **Font:** one font, `FONT_FAMILY` (GHEA Grapalat Bold, the only weight bundled, so every `FONTS.*` resolves to it). Copy a sibling component's Text style rather than inventing metrics.
- **Copy and labels:** UI copy is hard-coded uppercase Armenian, with no i18n layer. Accessibility labels are Armenian, and tests find keys by them.
- **Game icons:** custom icons (bow, coin, streak flame; `assets/icons/`, SVG components) follow `design-system.md`: read it and the existing icons first. Small utility glyphs (header, Hint button) use `expo-symbols` `SymbolView`.
