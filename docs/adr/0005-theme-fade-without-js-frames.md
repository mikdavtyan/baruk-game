# Theme fade: no JS work per frame, a split theme context

On a low-end Android (Redmi 10C, Expo Go) the toggle stuttered: the JS-driven text-color twin from ADR 0004 re-rendered every `Animated.Text` through React on every frame (Fabric), and the midpoint snapshot flip re-rendered the whole app because App itself read `isDark`. Now Text colors ride the same native-driven `progress` as View colors (`color` is on RN's native-animated allowlist), and the theme context is split in two: `useTheme()` (color, textColor, toggleTheme, reduceMotion, currentTheme — never changes on a toggle) and `useThemeSnapshot()` (`{ theme, isDark }`), read only by small leaf components (`components/ThemedSnapshot.tsx`, Coin, BowIcon, ArrowOverlay, …). A toggle is now zero renders per frame and one small re-render at the midpoint. Native text-color animation isn't confirmed to repaint on every Android device, so `TEXT_COLOR_NATIVE` in `constants/theme.ts` (default true) keeps a fallback: false switches text colors once at the midpoint while backgrounds still fade natively — still no per-frame JS work. Considered and rejected: React Compiler for the related keystroke re-renders — babel-preset-expo only applies it under Metro, so Jest would test uncompiled code and the render-count regression test couldn't guard it; we use `React.memo` plus stable props instead.
