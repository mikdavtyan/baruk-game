# Theme switch: a circle reveal over a snapshot

Supersedes the fade of ADR 0004 and the fade parts of ADR 0005 (its split theme context stays: `useTheme()` never changes on a switch, `useThemeSnapshot()` is read only by small leaves). The 2026-10 redesign wanted the new theme to spread in a growing circle from the pressed control (the Settings ՄՈՒԳ ԹԵՄԱ switch or the header's sun/moon), about 650 ms with a strong ease-out, smooth on a Redmi 10C in Expo Go. A per-view color fade can't do that, so the switch is now: snapshot the app's root view with Skia's `makeImageFromView`, mount a full-window Skia canvas showing it, switch the theme **instantly** underneath (the native-driven `progress` is only ever *set*, so no color is animated and nothing re-renders per frame), then grow a circular hole in the snapshot (`Group clip … invertClip`) from a Reanimated shared value on the UI thread, and unmount the canvas when it's open. This is a documented exception to "Animated only": Skia draws from shared values. The origin is `measureWindow` on the pressed control (null → the screen's center); taps mid-reveal are ignored; the choice is saved and the status bar flips at the switch; reduced motion, or a snapshot that can't be taken, switches instantly. `THEME_FADE_MS` and the `TEXT_COLOR_NATIVE` fallback are gone (nothing fades any more). Considered and rejected: `react-native-view-shot` plus an Animated mask — a second native snapshot path and a JS-side mask with no clip-by-circle primitive; Skia is Expo Go compatible and does both.
